# NigeriaStack.org — Corrected P0–P7 Implementation Recommendation v2.1
**Date:** 17 November 2026  
**Status:** Pre-execution recommendation and IA regeneration contract. No GitHub, Drive, DNS, Cloudflare, or production changes authorized or performed.  
**Basis:** Corrected Research Package Version 2 plus its canonically referenced current GitHub source documents `NS-KB-12`, `NS-KB-10`, `NS-KB-11`, `NS-KB-13` and source registries. This supplements, and corrects the IA deficiency in, `NigeriaStack_Implementation_Recommendation_v2_2026-11-17.md`.
## 1. Correction of the scope error
The former priority recommendation reduced the IA to 7 index routes, 7 H1s, and 15 H2 answer units. That omitted the governed descendant paths and H3–H4 requirements. `NS-KB-12` explicitly governs a master sitemap with dynamic route families and `Gate NS-G3` H1–H4 / `{copy_slot}` binding. The observed 102,855-character shell had 7 H1, 12 H2, 3 H3 and 1 H4 (source-string count, not a live browser certification).
The 15 `NS-ANSWER` headings from the Version 2 package do not replace the repo’s separate 15 canonical `RAG-H2` benchmarks. Both sets must be reconciled by semantic intent, hierarchy and authority; do not blindly concatenate duplicates or demote existing canonical sections.
## 2. Source-precedence conflict to resolve at P0
The seven Version 2 SEO metadata records contain H1 candidate strings that differ from H1 strings already locked via `NS-KB-12` / `NS-KB-10` / `NS-KB-11` `{copy_slot}` contracts. Under the established five-level source hierarchy, no new candidate automatically supersedes governed copy. Compare exact strings, retain the authoritative version until governed review changes it, and record any approved revised binding. Use the Version 2 SEO title, description and canonical candidates separately from H1 replacement decisions.
