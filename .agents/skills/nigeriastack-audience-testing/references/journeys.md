# Representative journey cards

Read the prompt to the participant. Keep routes and success conditions in the moderator's copy. Use a private review build, a device the participant ordinarily uses and a sample task with no personal records. Ask for permission separately if recording. Begin with a neutral introduction about what the session studies. Invite the participant to stop at any point. Ask them to think aloud where comfortable and preserve their usual assistive technology. [GOV.UK moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing) · [W3C guidance on involving users](https://www.w3.org/WAI/test-evaluate/involving-users/)

| Audience key | Neutral prompt | Moderator checkpoint and recovery probe |
| --- | --- | --- |
| `federal-steward` | An organisation wants to connect to a public register. Find out who can decide what data is shared and where you would verify that answer. | Start on Home. Participant finds safeguards, cites the charter or approved source and explains custodianship. Ask how they would find the responsible group if the first route does not answer the question. |
| `state-council-leader` | Your team is considering a service for Abuja Municipal Area Council. Find the council entry and tell us what evidence you have about adoption and who would decide whether to proceed. | Start on Atlas. Recognise AMAC and distinguish directory inclusion, candidate workflow, and readiness. Check how the participant resumes the search after following a link. |
| `enterprise-implementer` | You need to check what to do if a payment request times out. Find a relevant industry example and a source your engineering team can check. | Start on Industries. Finds the payments example, reports the evidential status and identifies the safe-retry reference or linked source. Observe what happens when a filter gives no results. |
| `software-implementer` | Find the specification referenced by NS-RFC-001. See what you can test on the site and describe what that result would establish. | Start on Specifications. Exact lookup finds the Hourglass reference, source link and lifecycle. Distinguishes the sample browser result from specification conformance and signed evidence. Observe recovery from an invalid sample check. |
| `resident-msme-litigant` | Using your phone, find the council that serves the named area. Tell us how you know you found the right entry and where you would check for official help. | Start on Home at a narrow mobile width. Use an unfamiliar but real council name from the directory. Confirm whether the participant can recover from a misspelling and understands what the directory establishes. |

Record the first action in the participant's terms, then successful and unsuccessful steps and the explanation they give. Ask them how they would recover before suggesting a route. A neutral follow-up is different from giving task assistance. Report first-action discovery, unassisted completion, assistance, recovery and route or authority confusion separately. Use issue IDs to associate failures with fixes. Attach a retest reference for each resolved blocker. For useful findings, record device, connection, input method and any setting that shaped the result. Observed users provide case evidence with limited generalisability.
